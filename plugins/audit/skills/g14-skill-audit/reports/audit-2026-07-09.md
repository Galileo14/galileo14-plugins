## Verdict

The skill still has all five controls present, wired and needed, with a
genuinely well-designed tiered fan-out, layered error handling and a
four-grader quality gate — the framework it defines is applied to itself
seriously. But the P1 bug flagged in the 2026-07-06 report is still live:
`scripts/scan_skill.py`'s orphan/wired detector mis-fires on the recommended
`${CLAUDE_PLUGIN_ROOT}/skills/<name>/<folder>/...` reference form, and this
run reproduced it live against a sibling skill (`g14-security-audit`'s
correctly-wired `assets/` folder comes back `wired: false, orphan: true`).
The reason last week's self-audit didn't catch it recurring is incidental:
this skill's own `SKILL.md` happens to *also* use bare-form paths
(`references/audit-rubric.md`, `scripts/scan_skill.py`, `tests/*.md`)
alongside the `${CLAUDE_PLUGIN_ROOT}` ones, so the bug never fires against
itself — but it fires against every other skill in the plugin, meaning any
future audit this tool runs against another skill can hand back a fabricated
❌ GAP. Fix `scan_skill.py` directly, not the target's wording around it.
Beyond that, most of last week's P2/P3 wiring gaps (Bash over-grant on
`dimension-auditor`, the calibration grader missing `audit-rubric.md` as an
input, the duplicate grounding/calibration check, the unspecified
grader-summary merge) are also unresolved, and this pass adds one new,
concrete finding: nothing in the skill tells its own auditors to treat a
target skill's file contents as inert data rather than instructions, even
though reading arbitrary (possibly third-party) skill folders is this tool's
entire job.

## Skill profile

What it does: audits a skill folder against the five-controls framework —
structural scan by script, pinned rubric reading, fresh dimension auditors in
parallel (grouped or per-dimension, scaled to target size), a fixed-template
report saved to a deterministic path, and a four-grader quality gate before
delivery.

Nature (drives which controls are needed):
- Input variability: high if unfixed — audit criteria would drift run to run
  without a pinned rubric; mitigated by `references/audit-rubric.md` +
  `references/best-practices.md` under a closed-world instruction
  (`SKILL.md:99`: "use ONLY these to judge").
- Process: split cleanly — the mechanical half (structural inventory:
  present/wired/orphan/agent config) is a deterministic script
  (`scripts/scan_skill.py`); the judgement half (is a control *needed*, is it
  done *well*) stays with the sonnet auditors.
- Output: fixed shape — `assets/report-template.md` with `{{SLOT}}`s, saved to
  a deterministic path `<skill_path>/reports/audit-<date>.md`.
- Parallelisable work: yes, and already fanned out — 2-6 dimension auditors
  (tiered by target size) plus 4 quality-gate graders, all dispatched in
  parallel.
- Correctness risk: high — the deliverable makes specific, falsifiable
  claims (`file:line`, scan-field values) about a third party's work;
  mitigated by the grounding/calibration/completeness/actionability gate,
  which puts the burden of proof on PASS.
- Runtime and scaling: 3-5 min for a small target (2-3 grouped auditors, then
  1 or 4 graders), 6-10 min for a large one (up to 6 per-dimension auditors,
  then 4 graders), per `SKILL.md:155-159`. For this skill itself,
  `sum(controls.*.file_count)` is 4+1+1+2+4 = 12, over the small-tier
  threshold of 8, so a strict reading of the Step 4 formula puts its own
  self-audit in the large tier even though `SKILL.md:49` describes it as the
  small/grouped case (see Control 4 below).
- Length and resumability: 7 steps; the scan JSON and each dimension's
  findings persist in context between steps, so no extra `state.json`
  checkpointing is needed at this length — a correct skip.

### Control 2: Process
- **Status:** PRESENT+WIRED+NEEDED (present-but-weak)
- **Evidence:** `scripts/scan_skill.py`, wired in `SKILL.md` Step 2, read-only by construction, with an explicit degrade path if it fails (retry once → manual inventory → mark verdicts `UNVERIFIED`).
- **Needed because / Skip is correct because:** N/A.
- **Assessment:** The infrastructure and error handling are sound, but the detector this skill depends on as ground truth has a confirmed, live bug. `scan_skill.py:180` computes `path_referenced` with `re.search(r"(?<![\w/])" + folder + r"/", skillmd)` — a negative lookbehind that rejects `folder/` when preceded by `/`. That's exactly the shape of the recommended reference form `${CLAUDE_PLUGIN_ROOT}/skills/<name>/assets/...`, where the character right before `assets/` is `/`. Reproduced live in this pass: `python3 scripts/scan_skill.py plugins/audit/skills/g14-security-audit` reports `3_output {present:true, wired_in_skillmd:false, orphan:true}` even though `g14-security-audit/SKILL.md:66` correctly references `${CLAUDE_PLUGIN_ROOT}/skills/g14-security-audit/assets/report-template.md`. This was flagged P1 in the 2026-07-06 report with the same root cause; it was not fixed in `scan_skill.py`. The only reason this skill's own self-audit doesn't currently trip it is that `g14-skill-audit/SKILL.md` happens to *also* reference its own folders in bare form (`references/audit-rubric.md`, `scripts/scan_skill.py`, `tests/*.md` — see `SKILL.md:42,46-48,200,203,240-243`), which independently satisfies the same regex. That's incidental self-protection, not a fix, and every other skill this tool audits is exposed. Second, unresolved issue (P3, carried over): `step_count`/`has_steps` (`scan_skill.py:292,309`) only recognize the literal token "step" adjacent to a number, so the `### N · Title` numbering used by all four sibling audit skills scores zero — reproduced live: `g14-security-audit` (4 clearly numbered steps) returns `step_count: 0, has_steps: false`, blinding the checkpointing cross-check for any skill using that convention.
- **Recommendation:** Fix `scan_skill.py:180` directly — either relax the lookbehind to `(?<!\w)` (drop `/` from the excluded set) or make `path_referenced` also true when a `${CLAUDE_PLUGIN_ROOT}/skills/<name>/<folder>/...` match (already extracted at lines ~240-248) resolves to this skill's own folder. Broaden the step-heading regex at `scan_skill.py:292` and `:309` to also match `#+\s*\d+\s*[·.:]` under a workflow/steps-shaped section.
